Z24 DATA SURVEY AND PREPARATION REPORT
======================================

1. Objective
-----------
Survey the Z24 raw data and build a Python/Jupyter pipeline to read signals, validate quality, create fixed-length windows, split the data, and export model-ready files.

2. Raw data
-----------
- Main file: raw_data/sources-Z24-004.zip (approximately 10.5 GB).
- Documentation: doc/Knowledge_based.pdf.
- Nested structure: outer ZIP -> Z24ems1/2/3.zip -> session ZIP (for example 01C14.zip) -> channel `.aaa` files (for example 01C1403.aaa).
- PDT packages contain `.mat` and `.aaa` files. The readme states that `.mat` files contain `data` and `labelshulp`. Sampling frequency is 100 Hz.
- `.aaa` files contain one channel as text: header, sample count, time step, signal values, and a footer describing units, acquisition segments, and settings.

3. Raw-data issue
-----------------
The outer ZIP is truncated. `Z24ems3.zip` is shorter than its declared size by at least approximately 88 MB. The pipeline does not modify raw data and skips that incomplete member. The ZIP should be re-downloaded or completed before final export.

4. Source files
---------------
- `z24_prepare.py`: ZIP reader, `.aaa` parser, windowing, splitting, normalization, and CSV export.
- `notebooks/Z24_prepare_training.ipynb`: pipeline execution, CSV preview, batch reader, and charts.
- `requirements.txt`: dependencies for a new machine.
- `Z24_USER_GUIDE.md`: usage instructions and limitations.

Install with `python -m pip install -r requirements.txt` from the `AI` folder.

5. Processing pipeline
----------------------
`inventory` reads outer ZIP headers and records names, sizes, offsets, and completeness. It is read-only. `prepare` selects complete EMS packages, opens sessions, reads numeric `.aaa` channels, validates sample count/time step/finite values, and stops signal parsing at `Timehistories end here`.

At 100 Hz, each 10-second window contains 1,000 samples. Incomplete tails and constant windows are dropped. Sessions are split approximately 70% train, 15% validation, and 15% test; all channels/windows from a session stay together. Train-only per-channel mean and standard deviation are then applied to every split.

Each session/channel is exported as CSV with columns `start_sample, sample_0, ..., sample_999`. `start_sample` is metadata for traceability; sample columns are the model input.

6. Smoke-test result
--------------------
With `MAX_SESSIONS = 20`: 20 sessions, 160 CSV shards, and 10,400 windows. Train contains 7,800 windows from 15 sessions; validation contains 1,040 windows from 2 sessions; test contains 1,560 windows from 3 sessions. Shape, dtype, finite-value, and session-isolation checks passed.

7. Labels and model evaluation
------------------------------
The current data has no verified healthy/damaged label column. Accuracy, precision, recall, F1, and a confusion matrix cannot be computed for damage classification until labels are joined by session/channel. Autoencoders or self-supervised models can be tested without class labels, but reconstruction loss alone does not validate damage detection.

8. Required next steps
----------------------
1. Complete or re-download the outer ZIP.
2. Confirm units, sensor locations, and acquisition-segment boundaries from documentation and `.aaa` footers.
3. Create a verified status-label table for each session.
4. Process all complete sessions and review charts.
5. Choose a time/condition-aware session split and recompute normalization using its training subset.
6. Train and evaluate only after labels and the evaluation split are confirmed.

9. Conclusion
-------------
The pipeline converts complete EMS channel signals into validated, normalized CSV windows and keeps session-level split isolation. The incomplete ZIP and missing verified labels currently prevent a defensible damage-classification result.
