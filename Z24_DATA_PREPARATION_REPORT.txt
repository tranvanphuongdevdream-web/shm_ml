Z24 DATA SURVEY AND PREPARATION REPORT
======================================

1. Objective
-----------
Survey the Z24 Progressive Damage Test (PDT) recordings and build a Python/Jupyter pipeline that validates MATLAB signals, preserves the documented condition labels, removes invalid samples, segments the recordings, and exports model-ready CSV files.

2. Raw data
-----------
- Main file: `raw_data/sources-Z24-004.zip` (approximately 10.5 GB).
- Documentation: `doc/Knowledge_based.pdf`.
- The archive contains two PDT packages: `pdt_01-08.zip` and `pdt_09_17.zip`.
- Each PDT package contains condition folders 01--17, `avt` and `fvt` measurement folders, setup folders, and MATLAB `.mat` files.
- Each MATLAB file is expected to contain `data` and `labelshulp`; the documented sampling frequency is 100 Hz.

3. Raw-data issue
-----------------
The outer archive is truncated after the PDT members: the later `Z24ems3.zip` member is incomplete by approximately 88 MB. The PDT cleaner ignores EMS members and does not modify the raw archive. Re-download the archive before the final completeness check.

4. Project files
----------------
- `prepare_pdt.py`: ZIP reader, MATLAB parser, finite-value cleaning, segmentation, PDT label mapping, and CSV export.
- `notebooks/PDT_cleaning.ipynb`: separate AVT/FVT full-export configuration and validation cells.
- `requirements.txt`: Python dependencies.
- `Z24_USER_GUIDE.md`: operating instructions and limitations.

Install with `python -m pip install -r requirements.txt` from the project folder.

5. Processing pipeline
----------------------
The cleaner opens the two PDT packages, parses each condition/setup/measurement path, and loads `data` plus `labelshulp`. Rows containing NaN or infinity are removed. The first 60,000 finite samples are retained and divided into ten consecutive segments of 6,000 samples. The notebook exports both AVT and FVT separately; the function can be limited to one measurement type when needed.

The condition directory supplies the class label. The mapping is explicit and reproducible: `label = condition_id - 1`, giving labels 0--16 for the 17 documented scenarios. Channel names are preserved per setup because channel order and count can differ between setups.

6. Output format
----------------
Each segment is written to `processed/avt/<run-name>/segments/*.csv` or `processed/fvt/<run-name>/segments/*.csv`. A CSV has one row per time sample, a `sample_index` column, and one column per sensor channel. `manifest.json` records the source, condition, label, setup, measurement, segment index, sample count, and channel names. `labels.csv` contains the complete condition-to-label table, and `report.json` records counts and issues.

7. Smoke-test result
--------------------
The full PDT export completed successfully: 306 recordings (153 AVT and 153 FVT) across conditions 01--17 produced 3,060 CSV segments (ten segments per recording), each containing 6,000 finite samples. No processing issues were reported. Manifest and CSV-count checks passed.

8. Model-evaluation considerations
----------------------------------
For multiclass classification, retain all 17 scenario labels. Conditions 1, 2, and 8 are reference or transition scenarios; any healthy/damaged binary grouping must be defined explicitly. Split at the setup or recording level before training so rows from one recording cannot leak across train and test. Compute normalization statistics from the training split only.
